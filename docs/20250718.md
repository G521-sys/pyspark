二,hive升级版本问题
![img_4.png](imgs/img_4.png)
解决步骤
1. 定位冲突的表
Hive Metastore 的表结构升级脚本（如 hive-schema-3.0.0.mysql.sql）中，OWNER_TYPE 通常会添加到 TBLS 表（存储表元数据）。

可通过以下 SQL 确认：
USE metastore;  -- 切换到 Hive Metastore 数据库（默认库名可能是 `metastore`）
SHOW TABLES;    -- 查看 Metastore 包含的表，找到可能涉及的表（如 TBLS、SDS 等）
2. 检查目标表的列
对疑似冲突的表（如 TBLS），查看其现有列：
DESCRIBE TBLS;  -- 查看 TBLS 表的结构，检查是否已有 `OWNER_TYPE` 列
如果输出中存在 OWNER_TYPE，说明该列已存在，升级脚本重复添加导致冲突。
3. 处理重复列的核心逻辑
根据 列的定义是否符合升级要求，选择以下方案：
场景 B：列已存在但定义与升级脚本不符
如果 OWNER_TYPE 的类型、长度等与升级脚本不一致（如旧版本是 VARCHAR(64)，升级脚本要改为 VARCHAR(128)），需 修改列定义 而非重复添加：
ALTER TABLE TBLS 
MODIFY COLUMN OWNER_TYPE VARCHAR(128) COMMENT 'Owner type of the table';
4. 预防重复升级（关键）
Hive Metastore 通过 VERSION 表 记录当前版本。如果重复执行升级脚本，会导致类似冲突。需检查：
SELECT * FROM VERSION;  -- 查看 Metastore 当前版本

USE metastore;  -- 切换到 Hive Metastore 数据库（默认库名可能为 `metastore`）
-- 查看表结构，确认索引所属表
SHOW CREATE TABLE TAB_COL_STATS;  
USE metastore;  -- 切换到 Hive Metastore 数据库（默认库名可能为 `metastore`）
-- 查看表结构，确认索引所属表
SHOW CREATE TABLE TAB_COL_STATS; 
检查索引是否已存在
通过以下 SQL 查看 TAB_COL_STATS 表上的索引：
-- 方法 1：直接查看表的索引
SHOW INDEX FROM TAB_COL_STATS WHERE Key_name = 'TAB_COL_STATS_IDX';

-- 方法 2：从系统表查询（更全面）
SELECT * FROM information_schema.STATISTICS 
WHERE TABLE_SCHEMA = 'metastore'  -- 替换为实际库名
  AND TABLE_NAME = 'TAB_COL_STATS' 
  AND INDEX_NAME = 'TAB_COL_STATS_IDX';
如果返回结果非空，说明 该索引已存在，导致升级脚本重复创建冲突。
索引已存在但定义与升级脚本不符
如果索引的列、类型等与升级脚本不一致（如旧索引列少、类型不同），需 先删除旧索引，再创建新索引：
-- 删除旧索引（注意：删除索引会影响查询性能，需评估）
DROP INDEX TAB_COL_STATS_IDX ON TAB_COL_STATS;  

-- 执行升级脚本中的 CREATE INDEX 语句（或手动补全正确定义）
CREATE INDEX TAB_COL_STATS_IDX ON TAB_COL_STATS(COLUMN_NAME, ...);  -- 替换为脚本中的完整语句
查看版本
SELECT * FROM VERSION;  -- 查看当前 Metastore 版本
